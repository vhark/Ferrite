## Platform findings (paid for in blood, do not regress)

1. **`AXManualAccessibility` must be applied lazily.** Setting it eagerly on every app poisons **Finder**: its `kAXWindowsAttribute` returns an empty array (AXError `.success`, zero windows) process-wide for the life of that Finder process. Finder was silently missing from every capture until this was found. It is now set only as a fallback when an app's first window query comes back empty (the Electron case it exists for). `AppObserver` must **not** set it either — the attribute is process-wide, so one eager write anywhere re-breaks Finder.
2. **Filter to the `AXStandardWindow` subrole.** Without it, enumerations include Finder's desktop window (full screen, empty title) and terminal tooltip/popup windows (~24×30). The old `> 1px` frame filter was far too weak.
3. **macOS gives no reliable "transient dialog" signal.** TextEdit's Open panel reports role `AXWindow`, subrole `AXStandardWindow`, `AXModal` false — indistinguishable from a document window. Mitigation: order-fallback matching is gated on `windows.count >= records.count`, so a relaunched app showing fewer windows than expected never has a transient window dragged into a slot. Title/pin matching still applies, which keeps apps whose titles drift (Arc) working.
4. **Minimized windows and hidden apps must be excluded from capture.** A minimized window keeps a plausible frame, becomes a layout member, and the raise pass un-minimizes it behind the user's back.
5. **Cross-app stacking needs app activation, not just `AXRaise`.** `AXRaise` orders windows *within* an app. Restoring a scene requires activating member apps backmost-first (spaced ~60ms so each activation lands), raising each app's own windows back-to-front inside its step.
6. **Ad-hoc signing re-keys TCC on every rebuild.** The Accessibility grant is bound to the code signature's designated requirement; `codesign -s -` changes the cdhash per build, so the grant silently dies and System Settings shows a stale enabled toggle. Fixed by signing with a self-signed **"MacTLM Dev"** identity (`scripts/make-app.sh` prefers it, falls back to ad-hoc). Toggling the grant while the app runs does not help; a stale entry must be removed and re-added, or reset with `tccutil reset Accessibility dev.mactlm.MacTLM`.
7. **`--list-windows` reports zero-window apps** with their raw AX window count and `AXError`. Findings 1 and 2 were both discovered through it; keep it.
8. **Excluded apps must still join the stacking cascade.** They are launch-only (frames never touched, PRD §9), so deriving activation order from `placements` silently omitted them — Illustrator launched last, activated itself, and covered the whole layout. `ApplyPlan.appStackingOrder` now ranks every active member by its frontmost window's zIndex, excluded ones included; `activateAndRaise` activates such an app without enumerating or raising its windows. Related: launch *start* order is not window *appearance* order, so launching backmost-first is a head start, never a guarantee — the cascade is what's authoritative.
9. **The Accessibility grant follows the signature, not the path.** Copying the signed bundle to `/Applications` and running it there needed no re-approval — verified 2026-08-20 by installing while the grant was live. Corollary: the grant also survived the macOS 26.6.2 update untouched. This is only true while a stable signing identity is used (see finding 6).
10. **`SMAppService.mainApp` registration is not a LaunchAgent.** Do not probe it with `launchctl print gui/$UID/<bundleid>` — that reports nothing even when registration is active. Use `--login-status` (which reads `SMAppService.mainApp.status`). Registration survives a `make-app.sh` rebuild of the same path, but the app should still live in `/Applications` (see `scripts/install.sh`) so wiping `build/` cannot break it.
11. **Adding a Codable field to a fail-soft store can destroy user data.** `LayoutLibraryStore.load()` returns an empty library on any decode error, and the next save writes that empty library back. So a new non-optional field on `LayoutLibrary` would have silently wiped a real `layouts.json` written before the field existed. Every new field needs an absent-tolerant `init(from:)` using `decodeIfPresent`, plus a test that decodes a literal legacy-shaped payload (`testLegacyJSONWithoutArchiveKeyStillDecodes`). Back up the live file before touching the format.
12. **KeyboardShortcuts 3.0.1 is `@MainActor`** (its `Package.swift` sets `.defaultIsolation(MainActor.self)`), while `PersistenceCoordinator` is nonisolated. Void-returning calls hop via `DispatchQueue.main.async`; the value-returning `shortcut(forBundle:)` is annotated `@MainActor` instead, since a hop would change its signature and `MainActor.assumeIsolated` needs macOS 14 (we target 13). Menu code that reads shortcuts needs `@MainActor` on the specific method — `NSMenuDelegate` callbacks are already isolated, so no cascade.
13. **Dynamic `KeyboardShortcuts.Name`s work and survive renames.** Names are built at runtime from the bundle name (`"bundle-<name>"`), and assignments live in `UserDefaults` under that name — so archiving a workspace keeps its hotkey (we simply stop registering a handler), and renaming migrates it with `getShortcut`/`setShortcut`/`reset`.
14. **Persisted window titles are a privacy leak, because the files are designed to be synced.** PRD §7 makes `layouts.json` and `configurations/*.json` git/Nextcloud-friendly, and titles captured browser page titles — i.e. browsing history — in plaintext. Fixed by storing `SHA-256(per-install salt ‖ title)` truncated to 16 hex chars. Matching fidelity is preserved because exact-window matching only ever needed *equality*, not the text. Untitled windows must hash to `nil`, never a shared constant, or every untitled window matches every other. Pins are unaffected: they are user-authored patterns tested against live titles in memory.
15. **A stopped-clock purge is not a purge.** Blanking titles on disk while the daemon ran was undone within seconds — the tracker holds records in memory and re-persists them. Any data-scrubbing operation has to either stop the writer first or ship in the writer itself.
16. **Namespace-scoped edits silently no-op.** `ConfigurationRecords.setPinPattern` guards on the record existing, so when the display configuration changed between the Preferences window rendering its rows and the user submitting a pin, the edit hit a namespace without that record and vanished with no error. Two lessons: a pin describes a *window*, not a monitor arrangement, so it now propagates to every namespace holding the bundle/slot; and any UI over per-configuration data needs a display-change hook to refresh (`PersistenceCoordinator.onConfigurationChanged`). Corollary, paid for again 2026-08-25: the Preferences window and its models are cached for the daemon's lifetime, so *every* store the UI renders needs a change hook — a menu-bar workspace save was invisible to the Layouts tab (even after reopening the window) until `onLayoutLibraryChanged` fired reloads from the library-write funnel, with a belt-and-braces model reload on window re-show.
17. **Dead migration code is worse than none.** `LayoutLibraryStore.loadPurgingLegacyTitles()` shipped with no caller, so `layouts.json` kept 18 legacy `title` keys, and only the *loaded* namespace was ever scrubbed — 3 of 4 config files kept theirs. Verified by grepping for callers on the real files, not by trusting the unit test that covered the unreachable function.
18. **A guard that drops work needs a recovery path.** M2a added `guard configKey() == loadedKey else { return }` to `noteActivity` so records for one display arrangement never land in another's file. Because `loadedKey` only moved when `didChangeScreenParameters` fired, a single missed notification killed persistence *silently and permanently* until relaunch — observed live: the store froze for four minutes while the app looked healthy and a separate watcher proved AX events were flowing. The guard now migrates (flush under the old key, adopt the live one, continue the capture) and reports via `onConfigurationDrift`. Rule: never silently drop user work to protect an invariant; repair the invariant and continue.
19. **Wholesale capture destroyed the records of windows that were merely closed.** `capture` replaced `records.apps[bundleID]` with whatever was open at that instant, so reopening one document of a two-document app pruned the other's remembered frame — then order-fallback matching dragged the late window onto the survivor's position. Both documents ended up stacked at the same pixel. Capture now MERGES: matched records update in place, unmatched live windows append, and records with no live window are preserved (capped at 16 per app, never evicting a pinned or just-matched record). Found only by waiting 3s between reopening two documents; M1's acceptance passed because it opened both within a second.
20. **One identity path, not two.** `assignPins` duplicated pin resolution alongside `WindowMatcher`'s pin phase. The merge rewrite deleted it so capture and restore cannot disagree about which window is which.
21. **An inherited exclude list is a set of assumptions, not measurements.** The default `ExcludeList` was seeded from Rectangle's known-hostile set and never checked against this app's own AX driver. `--probe-frame <bundleID>` settles it: it nudges the app's first eligible window by (40, 20), reads the frame back, prints requested vs achieved with an ACCEPTS/REFUSES verdict, then restores the original frame. Illustrator (2026-08-21) requested `(40.0, 50.0, 5841.0, 2130.0)` and achieved exactly that — it ACCEPTS frame changes, so it was removed from the defaults. After Effects and MATLAB were not running and stay excluded on Rectangle's authority until someone can probe them. Consequence: templates now *place* Illustrator instead of only launching it, so PRD §9's "launched, not placed" note no longer applies to it — and the excluded-app stacking path (finding 8) is exercised only by the two remaining defaults.
22. **A gesture threshold must be measured with a hand, not chosen in a unit test.** Mating geometry passed every property test at a 24pt reach but felt broken on a 7680px display. `MACTLM_TRACE_DRAG=1` measured deliberate attempts at 25–85pt with 0.98–1.00 perpendicular overlap; the only genuine near miss was a 23pt corner graze with overlap 0.02. The overlap gate prevents accidents, so reach is now 64pt while perpendicular alignment stays 24pt — coarse intent can be generous without silently straightening a deliberate offset. Four regressions lock the distinction. Follow-up 2026-09-02: the reach became user-configurable (`magnets.json`, Preferences → Magnets, clamped 8–128pt) with a 32pt default measured by the same hand — it is precisely this finding's core lesson, that overlap and not distance prevents accidents, that makes a distance knob safe to expose at all; the alignment threshold stayed a fixed 24pt, so a reach set below 24 also levels every mate's perpendicular edges. **Confirmed by hand 2026-09-05:** the 32pt default was tried live and preferred, which is the only kind of evidence this finding accepts — so 32 stays the shipped default rather than an untested halving.
23. **AX can report a resize that resized nothing.** During one ordinary drag, macOS emitted 14 `kAXWindowResizedNotification`s in 150ms with byte-identical previous/current frames. The M3b handler ended the drag session on every resized notification before checking geometry, so only the last moved events before mouse-up could establish a mate — making snapping require pinpoint aim. No-op resizes now return before identity/group AX sweeps or session mutation; only an actual width/height delta ends the move session and propagates to mates. Keep `MACTLM_TRACE_DRAG=1`: event timing, button state, candidate distances, suppression, and mouse-up outcomes have no headless test surface.
24. **A "last known frame" cache is poisoned by event twins.** An origin-moving resize (left/top edge drag) makes AX emit a moved notification before each resized one, and `WorkspaceMonitor` stores the frame when the moved twin is forwarded — so by the resized twin, `lastKnownFrame == event.frame` and the no-op guard (finding 23) ate genuine resizes: an 851pt width change was logged as a no-op. Consequences: live shared-edge propagation was dead for origin-moving drags since M3b, and M3c resize sessions opened only on lucky event ordering. Fix: the no-op guard and propagation's `previous` read a resize-scoped per-window cache in `MagnetDragSession`, refreshed by resized events and by frames we write; `lastKnownFrame` stays "newest frame from any event kind" for release-frame reads. Lesson: a cache serves the question it was built for — "newest frame" and "frame at the previous resized event" are different questions, and M3b's acceptance passed because the tested gestures happened to preserve the origin.
25. **A live gesture cannot ride synchronous AX writes.** Cluster-follow v1 wrote each follower's frame per moved event — synchronous IPC into every target app's main thread, sequential, so one busy member (Illustrator) stalled every tick and the user felt lag. macOS has no API to freeze another app's rendering, so the honest version of "don't render contents while moving" is ghost outlines: own panels moved with `setFrameOrigin` (window-server ops, zero IPC) at full mouse rate, and exactly one real write per follower at release, with the settle delta taken from the dragged window's real released frame (includes OS clamping mouse math would miss).
26. **Anchor gestures to at-rest state, then re-anchor on every authoritative event.** A drag session opens on the first AX moved event, 100–300ms after the hand starts moving, and that first event's frame is itself stale by processing time. Anchoring the formation at open baked the pre-open travel in as a permanent gap; anchoring drift to the first event still trailed on fast flicks. Fix, in two halves: the at-rest frame is free (`lastKnownFrame` is forwarded-before-stored, the same `previous` trick as findings 19/24), and every subsequent AX moved event re-anchors the ghosts while mouse ticks merely extrapolate between anchors — bounding the error to mouse travel within one event's latency, self-correcting many times per second.
27. **Shared-edge propagation is relative, not reversible — so any resize of a grouped window Ferrite did not initiate permanently destroys its mates' sizes.** A window *zoom* (title-bar double-click, or the green maximize button) is indistinguishable from a user resize at the AX layer: one `kAXWindowResizedNotification` filling the display. `openResize` correctly declined it (no mouse button held → programmatic), but live propagation still ran, through the `resize?.resizeMode ?? group.resizeMode` fallback, and squished the mates against the screen edges; un-zooming propagated again and could not restore them, because `MagnetResize.propagate` only ever slides a mate to follow a shared edge and holds no memory of the sizes it overwrote. **The first fix was wrong and live-disproved:** a global `.leftMouseDown` watcher that unmated the window "before the resize lands" still let the mates compress, because `NSEvent.addGlobalMonitorForEvents` is observe-only with no ordering guarantee against the target app — the app zoomed and AX posted the resize before our callback ran. Racing the window server is not a fix. **The real fix is to gate propagation on the invariant that already existed:** live propagation now requires an open `Resize` session, i.e. a mouse button actually held, which is exactly what `openResize` tests. A zoom, a script, an app resizing itself, and Ferrite's own unsuppressed `DisplayGroupReflow` writes all arrive with no button down and now propagate nothing, which also closes the reflow-suppression hole for free. The mouse-down watcher is kept, but only to drop the maximized window out of its group; its race is now harmless because a late unmate can no longer damage anything.

28. **Signing can block forever on an off-screen keychain prompt, so an unattended build must fail fast.** `scripts/install.sh` once sat for 15 minutes with no output past `replacing existing signature`: `codesign --sign "Ferrite Dev"` was waiting on a macOS authorization dialog for the key's private key, behind other windows. The keychain itself was unlocked (`security show-keychain-info` said `no-timeout`), so lock state is not the tell — `pgrep -fl SecurityAgent` is, and a live `SecurityAgent` means a prompt is up. "Always Allow" is required; plain "Allow" re-prompts every build, which is how an install that worked silently for a whole session starts hanging on a later day. Two consequences: the signing step in `make-app.sh` now runs codesign under a 45s deadline and exits with instructions rather than blocking, and piping `install.sh` through `tail` hides exactly the line that would have shown where it stopped — diagnose it with `bash -x` and unbuffered output.

## Next

- **Known defect: exclusion does not reach windows already in a magnet group.** Exclusion is enforced at gesture entry — `MagnetDragSession.eligibleWindows()` drops excluded bundles, so an excluded app cannot start a mate, be mated onto, or own a group — and `DisplayGroupReflow` skips them. But `PersistenceCoordinator.liveMembers(of:)` does not filter excluded bundles, and `setExcluded(true, …)` does not prune stored groups. So mate-then-exclude leaves stale membership that ⌘-drag cluster carry (`MagnetDragSession:189`), the group reflow row (`:225`) and Grow/Shrink frontmost (`:447`) all still move — contradicting "never moved or resized by any Ferrite mechanism". Also fires when `exclude.json` syncs from a machine where the app was already grouped. Two-part fix: prune the bundle from stored groups in `setExcluded` (dissolving any group that drops below two members — repair at the decision point, finding 18), and filter excluded bundles in `liveMembers(of:)` as defence in depth for the synced case. Documented in GUIDE with an Ungroup workaround; deferred until after M6 live acceptance so that protocol tests one known state.
- **M6 reflow presets v2 — IMPLEMENTED, pending live acceptance.** Five new built-ins in `GroupLayoutSolver` (`mainSideMirrored`, `mainCenter`, `bsp` dwindle spiral, `cascade`, `monocle`), user-defined custom presets (`fixedColumns`, `fixedGrid`, parameterized `mainCenter`) persisted in `reflows.json` and pinned into the menu's glyph rows, a Preferences → Reflows tab, two explicit reflow targets (display / group, plus a glyph row in every group's own submenu) replacing the one row that retargeted itself, and the display-reflow group policy (explode by default, keep behind one setting shared by the menu checkmark and the tab toggle). Independently, a third group resize mode `.standard` suppresses both shared-edge propagation and the M3c proportional settle. Builds; 259 unit tests, 0 failures. **Not in the shipped table**: no tag until the live acceptance protocol passes on the user's machine (see HANDOFF "Pending verification").

Research + full parity table: `docs/superpowers/specs/2026-08-25-tiling-parity-research.md`. ## Accepted residuals

| Item | Impact | Notes |
|---|---|---|
| `CFHash(AXUIElement)` as window id | Theoretical collision merges two windows | Cache is rebuilt per enumeration; revisit if ever observed |
| Clear-stage hides apps on *other* displays | Multi-display wart | Membership is per-display; resolve with bundles (M2b) |
| Snapshot dedupes by bundle ID | Second instance of one app is skipped | Rare; multi-instance support unscoped |
| Superseded template launch | Activation cascade for an abandoned plan can still fire within its ~60ms/app window | Inherent to spaced activation |
| ISO-8601 store dates | Sub-second precision truncated | Never compare live vs re-loaded records for equality |
| Login restore ordering | Startup sweep captures Resume-placed windows; arming settles for already-running remembered apps fixes the restore, but Resume still wins the first paint | Verified working; cosmetic |
| Launching an app does not reopen its documents | Document apps may come back empty (Open dialog) | Out of scope; finding 3 stops mis-placement |
| Keep-mode reflow of a group straddling two displays | Only the on-display members collapse into the cell; formation breaks across the seam | Membership survives; reflowing the group itself restores its shape |
| Explode-mode reflow dissolves a group having any member on the reflowed display | Membership lost for windows that may sit on another display | Deliberate: one member torn out already breaks the formation, and stale membership with broken adjacency is the documented footgun (finding 16's neighbourhood) |
| `reflows.json` drops unknown keys on save | A newer Ferrite's fields are lost if an older build saves the file | Bounded to not-yet-known fields; known fields always survive, which is what the absent-tolerant decode guarantees (finding 11) |
| Keep-mode reflow of a display holding nothing but one magnet group | The group scales up to fill the whole display, whatever preset was clicked | The mixed tile set has one tile, and `solve` short-circuits a single tile to the whole bounds before any preset runs. Preset-independent by construction; a lone group filling its display is the desired behavior. (A lone *ungrouped* window is never reflowed at all — `applyToDisplay` guards `members.count > 1`.) |

## Linux port (post-M2)

`FerriteCore` holds all schema, matching, planning, and solver logic with no AppKit import — that is the entire porting strategy. A Linux build needs a new `WindowDriving` implementation (sway/Hyprland IPC on Wayland, EWMH on X11). Approximately none of `Sources/Ferrite` is portable.
